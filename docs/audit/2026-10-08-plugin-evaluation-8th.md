# specops-ko 종합 평가 8회차 (2026-10-08, v2.8.0)

> **성격**: 동일 루브릭(5축·고정 가중)의 8회차. **방법이 처음으로 바뀌었다** — 종전 1~7회차는 저자 단독 측정이었고, 이번에는 독립 에이전트 5개(강제력·프롬프트 일관성·테스트·온보딩·실사용 데이터)가 각자 코드·데이터를 팠다. 자기 평가 편향을 줄이려는 변경이지만 없애지는 못한다 — 축 점수의 최종 판단은 여전히 저자(와 이 문서를 쓴 에이전트)의 것이다.
> **읽는 법**: 축·가중은 7회차와 같다. 그러나 **감사 깊이가 달라서 점수 하락의 일부는 '나빠짐'이 아니라 '처음 드러남'이다.** 아래 새 결함 중 다수는 7회차 시점에도 존재했을 것이다.
> **범위**: v2.8.0 릴리즈 커밋(`82787cb4`). 수정 PR #142 는 평가 후 반영이라 점수에 넣지 않았다.

## 새로 드러난 결함 (7회차 이후 처음 기록)

**침묵 실패**: ① 리뷰 재진입이 낡은 B/C 리포트 '존재'에 가려 무리뷰로 통과 ② `NEEDS_APPROVAL` 수신자 없음, `NEEDS_DISCUSSION` 처리 주체 없음 ③ R-2/R-1 면제 구멍 2건(재현·수정) ④ `check-task-receipt.sh` 거부 분기 20곳 중 13곳이 테스트로 보호되지 않음.
**하류 깨짐**: deny 메시지·doctor 처방·SKILL/agent 실행 지시의 plugin 상대 경로.
**경제성**: plan.md↔tasks.md 줄 74% 중복(골격 생성기 존재), `db_migration` 신호가 spec 의 `data-model.md` 언급만으로 걸림, R-1 마찰 로그의 31% 가 bypass 마커·같은 커밋 이중 기록.
**측정 불능**: 모든 receipt 의 `tdd_red` 가 `"unknown"`, ledger 시각이 일괄 기록, 6개 repo 중 4곳은 FID↔merge 연결 불가.

## 평가 후 조치 (점수 미반영)

PR #142 — 위 침묵 실패 ①②③④, 하류 경로, 테스트 구멍(hooks.json 등록·receipt·변이 게이트 matrix)을 수정했다. 두 면제 구멍은 수정 전 RED 로 재현했고, 감사 보고 중 외부 리뷰 dispatch 불일치(오탐)는 제외했다. 서브에이전트 편집이 앵커를 stale 로 못 만든다는 주장은 상태 파일(`verification-state.json`)이 있으면 트리 해시가 잡아 과장이었다(상태 파일 없는 구 FID 에만 잔여).

## 한계

- 에이전트 보고 중 일부는 오탐·과장이었다(위 2건). 수정 전 재현을 원칙으로 했으나 모든 항목을 개별 재현하지는 못했다.
- 실사용 데이터는 저자의 6개 repo, 대부분 저자 본인의 작업이다. 대조군이 없고 23개 FID 는 수정 후속이라 탈출 결함은 셀 수 없다.
- 점수는 같은 루브릭의 판단값이다. 감사가 깊어져 처음 드러난 결함이 점수를 깎았으므로, 7회차 대비 '품질 하락'으로 읽으면 안 된다.
