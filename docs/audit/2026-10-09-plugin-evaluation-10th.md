## 확인한 것 (직접 재현)

### 강제력

- **커밋 차단이 표기에 따라 빠진다.** 트리거가 `git` 글자 앞을 줄머리·구분자·env·래퍼 4종으로만 인정해 `/usr/bin/git commit`, `if …; then git commit`, `for …; do git commit`, `gh pr -R o/r create` 가 차단도 사후 감사도 거치지 않았다. 실기록: 하류 383건·본체 440건은 전부 인식, **이 저장소 worktree 의 80건 중 17건이 미인식** — 전부 평가자 자신의 절대경로 커밋이다(출력 필터를 피하려던 표기).
- **검증 PASS 뒤 셸로 코드를 고치면 커밋이 통과한다.** 판정 SoT(`verification-state.sh`)는 `STALE` 이라고 답하는데 훅은 transcript 의 Edit/Write 이벤트로만 무효화를 봤다.
- 진행 기록 한 줄만 있으면 **다른 FID 의 러너 출력**이 실행 증거로 통했다(`tasks.md` 없는 FID).
- `.specops/config.yaml` 로 훅을 끄면 실행 시점 기록이 없다(`/doctor` 에는 보인다) — Minor.
- 채점하지 않은 것(설계가 수용한 범위 — `docs/architecture.md` §6-1): 손으로 쓴 receipt · 가짜 러너.

### 기계적 완성도

- **must AC 커버리지 검사를 지운 채 전체 191 스위트가 통과했다.** 그 검사를 잠근다던 테스트가 앞 단계 게이트의 문안에 든 글자를 보고 통과했다.
- batch 에서 FR 을 멈추는 신호를 받는 쪽이 없다(`commands/start-all.md` 에 `NEEDS_APPROVAL`·`HOLD` 0건).
- 무인 모드의 plan 리뷰 한도 초과: `/start-auto` 는 자동 통과, `/start-all-auto` 는 Critical 이면 정지.
- 외부 critic(`critic-ask.sh`)이 하류 저장소에서 rc=1(템플릿 상대경로).
- main 브랜치 보호 없음 · 주간 변이 게이트 6주 연속 취소, matrix 개편 뒤 실행 0회.

### 온보딩

- **Stop 훅이 `.specops/` 없는 저장소에도 `session-progress.md` 를 만든다.** 그 뒤로 그 저장소의 코드 커밋이 R-1 로 막힌다 — README 의 "없으면 면제" 와 모순. 흔적 4곳(실제 차단이 일어났는지는 그 저장소들의 세션 기록이 없어 미확인). 자유작업 캡처·Stop 거버넌스·사후 감사도 같은 식으로 디렉토리를 만든다.
- `/doctor` 는 부트스트랩 전에는 아무것도 검사하지 않는다 — README 는 설치 직후 돌리라고 한다.
- 부트스트랩 직후 `/status` 가 오류로 끝난다.

고치는 과정에서 다시 확인한 것:

- **독립 리뷰가 매 묶음에서 실결함을 잡았다.** B 는 세 번 받았고 세 번 다 나왔다 — 1차: 새 전처리가 종전에 막히던 커밋을 열었다 · 2차: 새 예외가 `git rm` 한 파일을 놓쳤다(거짓 허용) · 3차: 감싼 `git add` 미탐과 인덱스 사본의 시각 문제. 세 번째에서 명령 글자를 해석하는 방식을 접고 기존 판정기를 재사용했다. 작성자의 자기 검토와 변이 실험만으로는 이 셋 중 하나도 나오지 않았다.
- **리뷰가 틀린 것도 있었다.** 감사 보고의 정정 5건(위)에 더해, 리뷰 지적 중 재현되지 않거나 선재 한계인 것은 반영하지 않고 PR 본문에 남겼다.
- A 의 CI 가 한 번 실패했다 — 테스트 2건이 개발 저장소의 `.specops/` 에 기대고 있었다. 이후 묶음은 `.specops` 가 없는 복제본에서 전체 스위트를 돌린 뒤 올렸다.

남긴 것(고치지 않았다):

- `sh -c`·`eval`·`xargs`·alias·변수에 든 커밋 명령은 인식하지 않는다(`docs/architecture.md` §6-1 — 수용한 범위).
- 추적 파일이 수천 개인 저장소에서 검증 지문 계산이 초 단위다(리뷰 실측: 4,800개에서 1회 약 11초).
- 인덱스에 올린 내용과 작업트리가 다르면(올린 뒤 작업트리만 되돌림) 지문이 보지 못한다.
- 하류 저장소의 `/doctor` `git_hooks` 경고는 조치할 것이 없는 채로 남는다(문구에 그렇게 적었다).
- 문서 계약의 잠금은 문장 존재를 본다 — 모델이 그 문장을 따르는지는 재지 않았다(`/start-all` 실주행 없음).

사람의 결정이 필요한 것:

- main 브랜치 보호(필수 검사 4종) — 저장소 설정이다.
- 주간 변이 게이트(`llm-smoke.yml`)의 matrix 첫 실행 — 수동 실행은 가능하나 장시간 작업이다.
- 경제성(경량 경로 사용 5/214) — 기본 경로를 바꿀지는 품질 근거가 필요한 정책 결정이다.
